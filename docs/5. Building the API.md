# Building the API

With your `OrderTracker` class complete and tested, it’s time to expose its functionality through a **Flask REST API**. The API will allow clients (including the provided frontend) to create, read, update, and list orders via HTTP requests.

For this part of the project, **all tests are already written for you** in `backend/tests/test_api.py`. Your job is to implement the route functions in `backend/app.py` so that these tests pass.

## What You're Building

The Order Tracker application demonstrates fundamental web development concepts through its core features, each mapped to a RESTful API endpoint:

1. **Add New Order**

    - **Endpoint**: `POST /api/orders`
    - Allows creation of new orders with details like `order_id`, `item_name`, `quantity`, `customer_id`, and optional `status`.

2. **Get Order Details by ID**

    - **Endpoint**: `GET /api/orders/<order_id>`
    - Retrieves the full details of a specific order using its unique ID.

3. **Update Order Status**

    - **Endpoint**: `PUT /api/orders/<order_id>/status`
    - Modifies the status of an existing order.

4. **List All Orders**

    - **Endpoint**: `GET /api/orders`
    - Retrieves a list of all orders currently in the system.

5. **Filter Orders by Status**

    - **Endpoint**: `GET /api/orders?status=<status>`
    - Filters the list of orders to show only those matching a specific status (e.g., `pending`, `shipped`).

## Steps to Complete

1. Open backend/app.py.
2. For each endpoint above, implement a Flask route function that:
    - Calls into your OrderTracker instance.
    - Returns JSON and the correct HTTP status code on success.
    - Returns an error message and appropriate code (404, etc.) on failure.
3. After implementing a route, run its tests:

    ```bash
    pytest backend/tests/test_api.py
    ```

    Iterate until the test passes.

4. When you’ve finished all routes, run the entire test suite:

    ```bash
    pytest
    ```

Everything (unit and API) should now pass.

## API Contract Reference

| Endpoint | Method | Request Body | Success Response | Error Cases |
| :--- | :--- | :--- | :--- | :--- |
| /api/orders | POST | JSON: { "order_id": str, "item_name": str, "quantity": int, "customer_id": str, "status": str (optional) } | 201 Created with order JSON | 400 Bad Request if input invalid; 409 Conflict if duplicate ID (depending on your implementation) |
| /api/orders/<order_id> | GET | – | 200 OK with order JSON | 404 Not Found if order doesn’t exist |
| /api/orders/<order_id>/status | PUT | JSON: { "new_status": str } | 200 OK with updated order JSON | 400 Bad Request if status invalid; 404 Not Found if order doesn’t exist |
| /api/orders | GET | – | 200 OK with list of all orders | – |
| /api/orders?status=<status> | GET | – | 200 OK with list of orders matching status | 400 Bad Request if status is empty or invalid |

## Tips

- Use Flask’s `jsonify()` to return responses:

    ```python
    from flask import jsonify
    return jsonify(order), 201
    ```

- For errors, return both a message and a status code:

    ```python
    return jsonify({"error": "Order not found"}), 404
    ```

- Keep the logic in `OrderTracker`. Your routes should just validate input, call the right method, and format the response.
- Use the **tests as your guide**. They are the ground truth for expected status codes and outputs.

## Trying the API Manually

The **proper way to verify your code** in this project is by running the automated tests. That’s how you know your implementation is correct and complete.

However, once all your tests are passing, you may find it interesting to **experiment with the API directly**. This can help you see how your Flask routes behave in practice, the same way a real client or the provided frontend interacts with them. This also may help with debugging, if you want to experiment with something that is not covered in the test suite.

In the Workspace, open a **new terminal window** in VS Code (menu bar → Terminal → New Terminal), and make sure your Flask server is running in the other terminal. Then you can run `curl` commands in the new terminal window.

- **Example: Add a new order (POST)**

```bash
curl -X POST http://127.0.0.1:5000/api/orders \
     -H "Content-Type: application/json" \
     -d '{
       "order_id": "CURL001",
       "item_name": "Headphones",
       "quantity": 1,
       "customer_id": "CUST123"
     }'
```

Expected response:

```json
{
  "order_id": "CURL001",
  "item_name": "Headphones",
  "quantity": 1,
  "customer_id": "CUST123",
  "status": "pending"
}
```

- **Example: Retrieve the order (GET)**
After creating the order above, you can fetch it with:

```bash
curl http://127.0.0.1:5000/api/orders/CURL001
```

Expected response:

```json
{
  "order_id": "CURL001",
  "item_name": "Headphones",
  "quantity": 1,
  "customer_id": "CUST123",
  "status": "pending"
}
```

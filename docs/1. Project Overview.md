# Project Overview

## Scenario

You are a software engineer at a small e-commerce startup. Your task is to build a minimal **Order Tracking** service using **Test-Driven Development (TDD)**. You’ll start with failing tests that describe the behavior of an `OrderTracker` class and a small Flask API. Following **Red → Green → Refactor**, you’ll implement just enough code to make each test pass, then iterate. By the end, you’ll expose RESTful endpoints to add orders, fetch them by ID, update their status, and list/filter orders. A lightweight in-memory storage backs the app (so data resets on restart), and a simple frontend consumes your API.

Key Learning Outcomes

- Use a test-first approach (Red → Green → Refactor) to drive backend logic development.
- Write maintainable unit tests using pytest.
- Build a RESTful API with Flask and test its integration points.
- Structure your tests for long-term clarity and scalability.
- Understand the role of debugging through test failures.
- Reflect on how real-world systems benefit from disciplined TDD.

## Before You Begin: Reflecting on Key Concepts

As you embark on building this Order Tracker, take a moment to reflect on the fundamental principles of software testing and TDD that are central to this course. Considering these questions will help you apply what you've learned directly to the project:

- **What is the primary role of test-driven development** in creating reliable software?
- How do you apply a **test-first approach** when implementing new features or functions?
- Why is it important to **structure your test** suites clearly and maintainably?
- How can you **interpret test failures** to efficiently diagnose and debug issues in your code?
- What are the benefits of using **unit tests** to verify individual components in isolation?

Reflecting on these questions will help you focus on the essential testing features you'll be implementing and reinforcing in this project.

## Application Structure

The frontend for this project has already been implemented for you. It provides a simple web interface where customers can add new orders, check the status of existing ones, and view lists of orders that are still pending or have already shipped. Your job is to build out the backend logic and API endpoints that power this frontend. Right now, the frontend will display errors because the backend is incomplete - your task is to eliminate those errors one step at a time.

## Development Process

To guide your progress, you’ll start by implementing the **core business logic** in the `OrderTracker` class. This layer is where the rules of your application live-preventing duplicate orders, validating updates, and organizing the data. Only after this logic is well-tested will you connect it to the **Flask API layer**, which handles HTTP requests and responses. This clean separation ensures that your application remains maintainable and testable: logic is independent of the web framework, and the web framework only needs to call into well-defined methods.

## CRUD Operations

As you build the backend, you’ll be covering core **CRUD (Create, Read, Update, Delete)** operations:

- **Create**: Add a new order.
- **Read**: Fetch an order by ID or list orders by status.
- **Update**: Change an order’s status (e.g., from `pending` to `shipped`).

The unit tests will guide you through each of these capabilities in turn. By implementing the backend in this order, you’ll see how a full set of CRUD operations emerges naturally from the TDD process.

## Application Goals

By the time you finish, the application will be fully functional:

- Customers can place new orders.
- The system will prevent duplicate order IDs.
- You can look up any order by its ID.
- You can update an order’s status (e.g., from `pending` to `shipped`).
- You can list all orders, or only those in a given status.

With both the logic and the API tested, you’ll be able to run the Flask server and interact with a working order tracker through the frontend or directly via API requests. You will write a brief README reflection after running your completed application.

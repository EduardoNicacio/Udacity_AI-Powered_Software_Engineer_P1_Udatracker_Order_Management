# Implementing Backend Logic

Once you have your application and tests running, your next milestone is to implement the **business logic** that powers the app. This logic lives in `backend/order_tracker.py` and is intentionally framework-agnostic (no Flask code here). You will **write tests first**, then implement just enough code to make each test pass.

You are provided **two example tests** to get started (`test_add_order_successfully` and `test_add_order_raises_error_if_exists`). After those, continue the TDD cycle by writing your own unit tests for the remaining behaviors and implementing the code.

```python
def test_add_order_successfully(order_tracker, mock_storage):
    """Tests adding a new order with default 'pending' status."""
    order_tracker.add_order("ORD001", "Laptop", 1, "CUST001")
    
    # We expect save_order to be called once
    mock_storage.save_order.assert_called_once()

def test_add_order_raises_error_if_exists(order_tracker, mock_storage):
    """Tests that adding an order with a duplicate ID raises a ValueError."""
    # Simulate that the storage finds an existing order
    mock_storage.get_order.return_value = {"order_id": "ORD_EXISTING"}

    with pytest.raises(ValueError, match="Order with ID 'ORD_EXISTING' already exists."):
        order_tracker.add_order("ORD_EXISTING", "New Item", 1, "CUST001")
```

## What You’re Building

The `OrderTracker` manages a simple order record with the following shape:

```python
{
  "order_id": str,        # unique ID (non-empty)
  "item_name": str,       # non-empty
  "quantity": int,        # positive integer
  "customer_id": str,     # non-empty
  "status": str           # one of: "pending", "processing", "shipped", "delivered", "cancelled"
}
```

### Core responsibilities

- Create an order (enforces uniqueness by order_id)
- Retrieve an order by ID
- Update an order’s status
- List orders (all or filtered by status)

These are **CRUD-style** operations (Create, Read, Update; Delete is out of scope).

## TDD Workflow

We’ve provided two example tests for adding an order. After that, you will write your own tests and implement the remaining methods. Work through them one at a time:

1. `add_order`
    - This method should add a new order, making sure it has valid fields and that no duplicate IDs are allowed.
    - Consider when testing: default vs. explicit status; duplicate IDs; invalid quantity; missing required fields; invalid initial status
2. `get_order_by_id`
    - This method should fetch an existing order by its ID, or return `None` if it doesn’t exist.
    - Consider when testing: existing vs. non-existent order; empty ID should raise
3. `update_order_status`
    - This method should change the status of an order. It should also validate that the order exists and that the new status is valid.
    C- onsider when testing: success path; invalid status (fail fast, no storage read); non-existent order; empty ID should raise
4. `list_all_orders`
    - This method should return all orders as a list of dictionaries.
    - Consider when testing: empty storage; multiple orders (order of results doesn’t matter)
5. `list_orders_by_status`
    - This method should return only the orders that match a given status.
    - Consider when testing: some match vs. none match; empty storage; empty/invalid status should raise

After implementing each method, run:

```bash
pytest backend/tests/test_order_tracker.py
```

## Tips

- Keep error messages **explicit** and **stable** (your tests will likely match on message text).
- When updating an order, avoid mutating the original dict from storage in-place unless you intend to-copy, update, and save is often clearer for tests.
- Prefer **small, focused tests** over large multi-assert "mega-tests."
